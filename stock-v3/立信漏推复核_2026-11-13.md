## 二、根因：不是「没查立信」，是「没识别流水线要求」

流水线 `a-share-pipeline.yml` 的**共同前置层** `common/prefilter.py` 明确要求：

- 条件② 立信审计剔除 → 产出 `common/state/lixin_exclude.json`
- 条件③ 生成 `common/state/universe.json`（已物理剔除 ST + 立信的样本池）
- 设计契约原文：**「任何下游模型（哪怕自身没写立信/ST 判断）都不可能选到」**

但 `common/registry.json` 里主升浪被登记为：

> 「自带 回溯/进化/选股/推送/云端备份 的**独立子系统**，**不消费共同前置层 universe/K线缓存**；settle=false 跳过公共回溯」

于是形成了这条漏筛链：

1. 主升浪走自己的 `datafetch.universe()` 拉候选池，**绕开**了流水线已剔除立信的 `universe.json`；
2. 它自己的立信防线只有 `每日推荐.apply_audit()` → `audit_check.main()` **联网实时抓东财公告**，且只查候选**前 18 / 前 40 只**，本身就有覆盖盲区；
3. `audit_result.json` / `audit_notices.json` / `audit_detail.json` 被 `.gitignore` 排除、**不入库** → GitHub Actions 干净 checkout 后无缓存，只能现场联网；
4. 11-13 东财云 IP **持续 502**（当日多个提交在抢修「云IP持续502」），公告大面积抓取失败 → `audit_check` 把大量票判为 `UNKNOWN`；
5. 旧 `apply_audit` 逻辑「只剔 `status=="LIXIN"`、`UNKNOWN` 当通过」→ **中重科技被当成「没查到=不是立信」放行**，进入主推并推送。

**本地沙箱此前没漏**，是因为本地留着 `audit_result.json` 缓存（含 `sh603135=LIXIN`）；云端无缓存 + 接口降级，缺口立刻暴露。这是「独立子系统」架构与流水线契约之间的空档，不是偶发抖动。

## 三、修复：新增 `lixin_gate.py`，四层防线

| 层 | 位置 | 作用 |
|---|---|---|
| ① 全量离线硬过滤 | `每日推荐.build()` 打分后、分层前 | 消费 `common/state/lixin_exclude.json`（775 只），对**全部 rows** 剔除；**不依赖联网**，东财 502 时仍生效 |
| ② 审计兜底 + 降级告警 | `apply_audit()` | 联网判定与离线名单取并集；`UNKNOWN` 比例高时打印醒目告警，不再静默放行 |
| ③ 推送前最终硬闸门 | `daily_v3.main()` record/推送之前 | 只要名单存在就**无条件**生效；主榜命中立信票则 `ABORT`，不 record、不推送、不污染台账 |
| ④ 首日观察榜双保险 | `firstday_board.py` | 立信票同样不进观察榜 |

**严格边界**（与既有形态闸门同级）：

- 不改 9 因子权重 / cdf / 打分 / 百分位 / 排序 / 板块配额 / 交易规则；
- 不触碰 `model2.P`、`factor_fit.json`、`holdout.json`；
- 不写 `predictions.json` / `feedback_db` 等状态，不参与结算、不触发进化；
- `LIXIN_GATE=off` 回退「打分阶段过滤」（A/B 对照）；`LIXIN_GUARD=off` 才解除推送前终检，两者独立；
- 名单缺失/异常降级放行并告警，绝不阻断主闭环。

改动的 4 个文件：`lixin_gate.py`（新增）、`每日推荐.py`、`daily_v3.py`、`firstday_board.py`。
